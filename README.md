# 麦团餐官 · 一句话需求，出一份能直接发客户的团餐方案

> 基于麦当劳 MCP 的企业团餐 Skill。你说「明天中午 20 人开会，人均 40」，它给你：能接的门店、卡得住的配比、三档助餐服务的真实差价，以及一份可以直接转发给客户行政的方案。

```bash
python3 scripts/tuancan.py plan --address-id <你的地址ID> \
    --people 20 --per-head 40 --at "2026-10-26 12:00" --scene 会议
```

跑完就是这样一份东西（[完整输出](examples/01-会议餐-20人-人均40.md)）：

| 助餐档位 | 含什么 | 20 人应付 | 人均 | 比基础档贵 |
|---|---|---|---|---|
| 保鲜速达 | 准时送达 + 保温 | ¥601.00 | ¥30.05 | — |
| **专人分餐** | + 送餐到人/到桌 | **¥681.00** | **¥34.05** | +¥80.00（人均 +¥4.00） |
| 专人摆台 | + 餐品摆台 + 专人服务 | ¥721.00 | ¥36.05 | +¥120.00（人均 +¥6.00） |

---

## 为什么不做一个「套餐推荐助手」

因为团餐真正会卡住的，从来不是「点什么」。是这四件事：

| 卡点 | 普通点餐助手 | 麦团餐官 |
|---|---|---|
| **这家店能不能接、几点能接** | 查不到 | 按 `reservationTimeOptions` 校验，精确到「午餐 12:00至15:59」 |
| **要的助餐服务来不来得及** | 不知道有这回事 | 4 小时硬线前置拦截，自动降级并说明原因 |
| **人均预算怎么落成具体餐品** | 随机凑 | 按官方配比 + 预算穷举，贴着预算上限出单 |
| **三档助餐服务分别多少钱** | 报不出 | 同菜品三档并行算价，直接给"每人多几块" |

**团餐的助餐服务不是"加钱买服务"——档位本身会改变折扣。** 同一单 800 元商品，选保鲜速达是 601 元，选专人摆台是 721 元。客户问你要不要加专人分餐，答案是一个具体数字，不是一句"会更贵一点"。

## 三个从真实接口跑出来的结论

### 1. 4 小时是一条硬线，不是建议

`query-meal-assistance` 会返回 `unusableReason`：专人分餐和专人摆台都要**提前 4 小时**预约。这是团餐最高频的翻车点——客户中午 11 点说"下午两点半的会，要有人送到座位上"。

工具不会让你在下单那一刻才发现，它在生成方案时就拦住（[完整输出](examples/03-紧急单-只剩2.8小时.md)）：

| 档位 | 应付 | 可约 |
|---|---|---|
| 保鲜速达 | ¥601.00 | ✅ |
| 专人分餐 | 不可约 | ⚠️ 距开餐只剩 2.8 小时，需提前 4 小时 |
| 专人摆台 | 不可约 | ⚠️ 距开餐只剩 2.8 小时，需提前 4 小时 |

### 2. 团餐菜单接口不给价格，但算价接口会漏

`query-meals` 只返回餐品编码和标签，没有名字也没有价格。逐个调 `query-meal-detail` 会把请求数打爆（限流 600 次/分钟）。

**做法：一次塞十几个商品进 `calculate-price`，每个 `quantity: 1`，它会把这批商品的单价全部吐回来。** 十来个商品一次调用，比逐个查详情省一个数量级的请求。

```python
items = [{"productCode": c, "quantity": 1} for c in codes]   # 一次 12 个
quote = mcp.call_tool_data("calculate-price", {..., "items": items})
# quote["productList"] 里每个商品都带 originalSubtotal = 单价
```

### 3. 下午茶和会议餐不是同一套配比

同一笔 25 元/人的预算，配「吉士汉堡包 + 苹果片」是错的，配「中薯条 + 饮品」才对。场景必须能改组合结构，不能一套配比走天下。

| 场景 | 结构 | 默认助餐档 |
|---|---|---|
| 会议 / 培训 | 主食 + 小食 + 饮品 | 专人分餐（不打断节奏） |
| 下午茶 | 小食 + 饮品 | 保鲜速达 |
| 团建 / 发布会 | 更丰盛的组合 | 专人摆台 |

## 60 秒跑起来

**1. 拿 MCP Token**：手机号登录 [open.mcd.cn/mcp](https://open.mcd.cn/mcp) → 右上角「控制台」→「激活」→ 同意协议 → 复制 Token。

**2. 配好环境**（只依赖 Python 3.8+ 标准库，不用装任何包）：

```bash
export MCD_MCP_TOKEN="你的 Token"
```

**3. 跑起来**：

```bash
python3 scripts/tuancan.py addresses                                  # 看有哪些配送地址
python3 scripts/tuancan.py stores --address-id <地址ID>                # 看能做团餐的门店
python3 scripts/tuancan.py plan \
    --address-id <地址ID> --keyword 徐汇万科 \
    --people 20 --per-head 40 --at "2026-10-26 12:00" --scene 会议
```

参数说明：

| 参数 | 说明 |
|---|---|
| `--people` | 人数 |
| `--per-head` | 人均预算（元） |
| `--at` | 送达时间，`YYYY-MM-DD HH:MM` |
| `--scene` | `会议` / `培训` / `下午茶` / `团建` / `发布会` / `加班餐` |
| `--keyword` | 门店名关键词，不填就用第一条 |
| `--tier` | 指定助餐档位，不填按场景默认 |
| `--out` | 写到文件而不是打到终端 |

## 它怎么工作

```
需求（人数 / 人均 / 时间 / 场景）
   │
   ├─ delivery-query-stores(beType=6)      → 能做企业团餐的门店 + 团餐预约时段
   ├─ reservation_check()                  → 你要求的时间点是否落在某个团餐时段内
   ├─ query-meal-assistance(beType=6)      → 三档助餐服务 + 可用性 + 4h 闸门
   ├─ query-meals(beType=6, orderType=2)   → 团餐菜单（只有编码，没有价格）
   ├─ probe_prices()                       → 批量钓价（12 个一批）
   ├─ choose_structure()                   → 按场景 + 预算，选能撑住的最丰富结构
   ├─ build_combo()                        → 穷举求最优：先比"像不像人点的"，再比贴不贴预算
   └─ calculate-price() × 3                → 三档并行算价，出对比表
         │
         └─ render() → 一页可转发给客户的方案 + 报价单
```

**为什么用穷举而不是贪心**：结构最多 5 件、每类候选十几个，组合空间在 10⁴ 量级，穷举毫秒级跑完，还不用调参。贪心的那个版本会把预算全砸在主食上，最后凑不出小食，然后塞一包 3 块钱的蘸酱进来——真实发生过，所以换掉了。

## 用到的麦当劳 MCP 工具

| Tool | 在这做什么 |
|---|---|
| `delivery-query-addresses` | 取配送地址 ID |
| `delivery-query-stores` | `beType=6` 查企业团餐可用门店 + 预约时段 |
| `query-meal-assistance` | 三档助餐服务、`gmServiceCode`、可用性与 4h 限制 |
| `query-meals` | 团餐菜单（分类 + 编码） |
| `calculate-price` | 批量钓价 + 三档算价（含折扣、打包费、配送费） |
| `query-meal-detail` | 单品详情与可特制选项（可选） |

详见 [MCP_INTEGRATION.md](MCP_INTEGRATION.md)。

## 边界

- **不做自动下单**。`create-order` 能真花钱，工具只出方案，下单由人点最后一下。这是刻意留的。
- **价格和库存以官方渠道为准**。这里的数字是麦当劳 MCP 接口的实时返回，但你最终看到的页面才是最终价。
- **不处理个人信息**。方案里只有门店、菜品、价格、时间，没有手机号和联系人。
- **团餐的履约细节**（发票抬头、变更规则、超时补偿）因门店而异，工具不臆造，留给你和门店确认。
