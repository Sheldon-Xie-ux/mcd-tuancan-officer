# 麦团餐官 · 团餐的两头都管：事前出报价，事后出结算单

> 基于麦当劳 MCP 的企业团餐 Skill。
> 团餐真正折磨人的不是「点什么」，是**同一笔钱要算两遍**：下单前算一遍报价，月底结算再算一遍，中间那笔差额谁也说不清。
> 这个工具管两头——事前给你一份能发客户的报价，事后给你一份能交财务的结算单。

```bash
export MCD_MCP_TOKEN="..."                                  # open.mcd.cn/mcp → 控制台 → 激活

# 事前：一句话需求 → 报价单
python3 scripts/tuancan.py plan --address-id <ID> --keyword 徐汇万科 \
    --people 20 --per-head 40 --at "2026-10-26 12:00" --scene 会议

# 事后：订单 → 结算单（含按部门分摊）
python3 scripts/settle.py order --order-id <ID> --shares "研发:12,市场:5,行政:3"
```

## 事后这一半：把账算到分

团餐结账最容易出事的地方，不是总额，是**分摊之后合计对不上**。财务不认「四舍五入差一分钱」。

同一笔 ¥31.90，按三个部门权重拆，用**最大余额法**分尾差：

| 部门 | 权重 | 应分摊 | 占比 |
|---|---|---|---|
| 研发 | 12 | ¥19.14 | 60.0% |
| 市场 | 5 | ¥7.98 | 25.0% |
| 行政 | 3 | ¥4.78 | 15.0% |
| **合计** | **20** | **¥31.90** | **100.0%** |

三项加起来和实付**分毫不差**。这不是展示技巧，是财务会当场核的东西（[完整输出](examples/04-结算单-按部门分摊.md)）。

结算单里还有三段：

| 段落 | 干什么 | 为什么需要 |
|---|---|---|
| 金额核对 | 商品行 / 配送费 / 折扣 / 券 / 实付，五项对平，差额算到分 | 「这单怎么比报价贵了」有个能拿出来的答案 |
| 商品明细 | 逐行拆到套餐子项 | 少送一份、替换一款，一眼能定位到行 |
| 事后检查 | 评价券、账户券状态与**可用窗口** | 券不是拿到就能用，见下 |
| 异常登记 | 少送/迟到/替换的信息集模板 | 电话里扯不清的事，一条消息说完 |

### 券有可用窗口，拿到不等于能用

`query-my-coupons` 返回的券带 `instructions.labels` 和 `availableTime`。真实数据长这样：

| 券 | 状态 | 可用窗口 |
|---|---|---|
| 11.9元麦辣鸡腿堡 | 未到使用时间 | 2026.10.26-2026.10.30 ｜ 周一至周五 |
| 19.9元王牌炸鸡任选2 | 未到使用时间 | 2026.10.26-2026.10.30 ｜ 周一至周五 |

**「账户里有 2 张券」和「这 2 张券现在能省 30 块」是两件事。** 只报「你有 2 张券」的工具，等于没告诉你最关键的那半句。

## 事前这一半：一句话出报价

说完人数、人均预算、时间和场景，直接给一份能转发给客户行政的东西（[完整输出](examples/01-会议餐-20人-人均40.md)）：

| 助餐档位 | 含什么 | 20 人应付 | 人均 | 比基础档贵 |
|---|---|---|---|---|
| 保鲜速达 | 准时送达 + 保温 | ¥601.00 | ¥30.05 | — |
| **专人分餐** | + 送餐到人/到桌 | **¥681.00** | **¥34.05** | +¥80.00（人均 +¥4.00） |
| 专人摆台 | + 餐品摆台 + 专人服务 | ¥721.00 | ¥36.05 | +¥120.00（人均 +¥6.00） |

客户问「要不要加专人分餐」，答案是一个数字，不是一句「会更贵一点」。

### 三个刻意的设计

**1. 档位会改价格，不只是加服务。** 同一单商品原价 ¥800，选保鲜速达是 ¥601，选专人摆台是 ¥721。因为档位对应不同的助餐折扣。要同时调三次算价接口才看得见这条规律。

**2. 专人分餐和专人摆台要提前 4 小时。** `query-meal-assistance` 会返回 `unusableReason`。工具在**生成方案时**就拦住，而不是等你下单才报错（[只剩 2.8 小时的案例](examples/03-紧急单-只剩2.8小时.md)）：

| 档位 | 应付 | 可约 |
|---|---|---|
| 保鲜速达 | ¥601.00 | ✅ |
| 专人分餐 | 不可约 | ⚠️ 距开餐只剩 2.8 小时，需提前 4 小时 |

**3. 场景会改组合结构。** 同样 25 元/人，给下午茶配「吉士汉堡包 + 苹果片」是错的，配「中薯条 + 饮品」才对。一套配比走天下，是没在团餐里踩过坑的人才会做的事。

### 团餐菜单接口不给价格，但算价接口会漏

`query-meals` 只返回餐品编码和标签，没有名字也没有价格。逐个调 `query-meal-detail` 会把请求数打爆（限流 600 次/分钟）。

**做法：一次塞十几个商品进 `calculate-price`，每个 `quantity: 1`，它会把每个商品的单价都吐回来。** 一批 12 个，二三十个商品 2–3 次请求拿全。比逐个查详情省一个数量级。

```python
items = [{"productCode": c, "quantity": 1} for c in codes]
quote = mcp.call_tool_data("calculate-price", {..., "items": items})
# quote["productList"][*] 每项都带 originalSubtotal = 单价
```

## 60 秒跑起来

**1. 拿 Token**：手机号登录 [open.mcd.cn/mcp](https://open.mcd.cn/mcp) → 右上角「控制台」→「激活」→ 同意协议 → 复制。

**2. 配环境**（纯 Python 3.8+ 标准库，不装任何包）：

```bash
export MCD_MCP_TOKEN="你的 Token"
```

**3. 跑**：

```bash
python3 scripts/tuancan.py addresses                       # 有哪些配送地址
python3 scripts/tuancan.py stores --address-id <ID>        # 哪些门店能做团餐
python3 scripts/tuancan.py plan --address-id <ID> \
    --people 20 --per-head 40 --at "2026-10-26 12:00" --scene 会议
python3 scripts/settle.py list                             # 历史订单
python3 scripts/settle.py order --order-id <ID> --shares "研发:12,市场:5"
python3 scripts/settle.py month --month 2026-10            # 月度结算
```

| `plan` 参数 | 说明 |
|---|---|
| `--people` | 人数 |
| `--per-head` | 人均预算（元） |
| `--at` | 送达时间 `YYYY-MM-DD HH:MM` |
| `--scene` | `会议` / `培训` / `下午茶` / `团建` / `发布会` / `加班餐` |
| `--keyword` | 门店关键词，不填用第一条 |
| `--tier` | 指定助餐档位，不填按场景默认 |

## 边界

- **不自动下单**。`create-order` 会真扣款，工具只到「报价 + 结算」为止，中间那一下由人点。
- **价格以官方为准**。这里的数据是麦当劳 MCP 接口的实时返回。
- **不处理个人信息**。方案和结算单里只有门店、菜品、金额、时间。
- **发票与索赔结果不臆造**。接口不返回开票信息，不同门店规则不同，只给材料清单。
